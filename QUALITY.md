# Repository Quality Gates

Use Node **24.11 or newer**, preferably Node 24 LTS (`nvm use`), and the committed npm lockfile. The newer Node requirement is for development analyzers, not the extension host or OMP process. Do not install the analyzers with Node 18. The shared runner launches child tools using the same interpreter as itself.

```sh
npm ci
npm run check
```

`check` fails fast on formatting, lint, strict type checks, quality-tool self-tests, fresh deterministic coverage, metrics/budgets, and architecture fitness. It does not rewrite files, update baselines, launch a model, install the extension, or touch a user's repository. Tests use disposable filesystem fixtures. VS Code's default Test task runs this command.

On this Linux machine, the VS Code executable also supplies a compatible Node runtime:

```sh
ELECTRON_RUN_AS_NODE=1 /usr/share/code/code scripts/quality.mjs check
```

## Quiet Linux Native Tests

Linux native, release and separately authorized live tests default to `VS_OMP_TEST_DISPLAY=quiet`. The direct extension, terminal-probe and crash/reopen runners use the same policy. One owned Xvfb display wraps the full gate; child workbenches inherit it rather than opening on the user's desktop. Openbox supplies real window management at 1440x900, 24-bit color and 96 DPI. A private D-Bus session starts inside that display, with a separate runtime directory and no inherited Wayland, keyring-control or accessibility-bus endpoints. This is display/session isolation, not an OS sandbox or a new inference allowance.

On Debian/Ubuntu Linux x64, prepare the tools once:

```sh
npm run setup:test-display
npm run test:display
npm run check:native
```

The setup uses the host's configured APT repositories and existing signed package indexes. It only downloads and extracts packages into ignored `.local-dev/test-display/`; it does not use sudo, install system packages, change desktop settings or start GUI applications. A private package receipt records versions, archive SHA-256 hashes and resolved tools. Existing system tools are also supported. Missing prerequisites or invalid display modes fail clearly, never falling back to the real desktop. The bootstrap currently supports Debian/Ubuntu x64; other Linux hosts must provision Xvfb, xvfb-run, xauth, Openbox, D-Bus and the wmctrl/xdpyinfo verification utilities themselves.

Using VS Code's embedded Node on this machine:

```sh
ELECTRON_RUN_AS_NODE=1 /usr/share/code/code scripts/setup-test-display.mjs
ELECTRON_RUN_AS_NODE=1 /usr/share/code/code --test quality/test-display.test.mjs quality/test-display.integration.mjs
ELECTRON_RUN_AS_NODE=1 /usr/share/code/code scripts/quality.mjs native
```

Visible acceptance is explicit and may interrupt the desktop:

```sh
VS_OMP_TEST_DISPLAY=visible npm run check:native
```

All existing native assertions and twelve deliberate crash/reopen stages remain required. Real Electron rendering, Playwright keyboard/focus, native workbench notifications, PTYs, installed OMP and screenshots are retained. The disposable VS Code profiles use `--password-store=basic` so a fresh isolated bus does not request the user's keyring; these profiles must never receive real VS Code login credentials. OMP's existing model-discovery authentication is unchanged. Actual desktop notifications, compositor/focus-stealing behavior, hardware GPU rendering, encrypted desktop storage and screen readers require separate intentional visible/manual acceptance; virtual-display success does not certify them. Non-Linux hosts retain visible behavior by default and are not newly certified.

Private evidence lives in ignored `reports/test-display/run-*/`: session display, bus-address hash, window-manager PID, logs and final status/duration. Authority material is removed on normal completion, failure and handled SIGINT/SIGTERM. These paths are not hosted artifacts. As with other fixtures, SIGKILL or machine failure cannot execute cleanup handlers. The required native gate also verifies simultaneous distinct displays/buses, geometry/DPI, successful and nonzero exit preservation, SIGTERM cancellation and cleanup of a TERM-resistant child after window-manager failure. No visible fallback or test-stage removal is permitted.

## Metrics And Limits

Production TypeScript, tests, browser JavaScript/CSS, tooling scripts and root JavaScript configuration are measured. Generated output, vendored code, private spike output, JSON and Markdown are not code-size targets. CSS receives a file-length check only.

| Metric              | Default maximum | Definition                                                  |
| ------------------- | --------------: | ----------------------------------------------------------- |
| McCabe cyclomatic   |              10 | ESLint's classic `complexity` rule, per function            |
| Cognitive           |              15 | SonarJS `cognitive-complexity`, per function                |
| Function length     |        80 lines | Inclusive physical source lines, including declaration head |
| File length         |       500 lines | Physical source lines, excluding final newline              |
| Halstead volume     |          30,000 | File aggregate from typhonjs-escomplex-module               |
| Halstead difficulty |             150 | Same file-level profile                                     |
| Halstead effort     |       4,000,000 | Same file-level profile                                     |
| CRAP                |              30 | Per production function, using measured unit line coverage  |

Halstead uses TypeScript 6 type-erased ES2017 normalization before Babel/escomplex analysis. This makes modern syntax measurable by the older analyzer, but generated helper/lowered syntax contributes to the result. It is not a raw-TypeScript token count. The legacy analyzer has a deprecated development-only dependency; the separate packaging/architecture advisory was withdrawn upstream and fresh audits are clean. See [Toolchain Assessment](#toolchain-assessment). Replacement must revalidate fixtures and explicitly review baseline comparability.

CRAP is `C² × (1 − coverage / 100)³ + C`, where `C` is classic McCabe complexity. Unexecuted functions receive zero coverage, including files with synthetic empty coverage reports. Covered-line percentages are approximate function-local statement-line coverage, not branch/path proof. Anonymous callbacks are identified by declaration/ancestor names and occurrence, not line number; renaming or inserting similarly named callbacks may require explicit baseline migration.
